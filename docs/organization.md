# 文件整理

## 用户规则

默认按拍摄当天归档，不等于导入当天。目录层级提供 `YYYY-MM-DD`、`YYYY/YYYY-MM-DD`、`YYYY/MM/YYYY-MM-DD`，不开放任意路径脚本或可执行模板。

也可按导入日期、保留卡内目录或不分类。可选类型隔离位于日期／原始父目录内部：NEF、NRW → RAW；JPG、JPEG → JPG；MOV、MP4、AVI → VIDEO；TIF、TIFF → TIFF。原文件名不改变，冲突沿用完整内容校验和哈希后缀。

可靠拍摄时间缺失默认放入“未知日期”。用户可明确选择按源文件修改时间归档；来源在确认框中展示。文件创建时间、电脑当前日期和文件名序号不会被猜成拍摄日期。

照片优先使用 EXIF 原始拍摄时间。默认保留相机记录的日历日期；视频整数时间是否为 UTC 是显式选项，不对所有相机强制转换。使用 UTC 转换和修改时间回退时，时区作为整理规则的一部分冻结。同目录同文件主名的 JPG／RAW 可在只有一个可靠日期且没有日期冲突时共用日期，不跨相机文件夹推测配对。

## 规划与交互

文件整理为全局配置，入口为“设置 → 文件整理”。表单提供实时示例。导入确认展示规则、分组、未知／回退日期数量及首选位置下的实际路径。确认框“更改”关闭旧确认并打开设置；再次执行只读规划和预检，不能沿用旧路径或旧确认。

按导入日期的日期在规划时冻结，不在午夜、重试或位置回退时重新计算。该模式的展示缓存包含当前日期，跨日会失效。修改整理规则也使候选缓存失效。暂停或取消不创建目标目录。

## 数据与安全边界

源 `RelativePath` 始终是 SD 卡内真实路径，源校验和清理仍使用它。`TargetRelativePath` 独立保存分类后的相对路径，禁止绝对路径、越级、保留设备名和 partial，必须保留源文件名。Windows／SMB 和 HTTP／对象存储都在自己的已批准根目录内使用同一个相对路径。

元数据在隔离规划进程中、源及祖先锁定期间只读解析；解析前后检查源快照及卡片身份。解析器有字节、偏移、层级和循环边界，不解码整张照片或顺序读完整视频。无法理解的格式进入未知日期；结构损坏不能产生不受限路径或绕过源校验。

本地和 WebDAV 只在实际复制／上传时按需创建父目录；S3 使用对象键前缀，不创建伪造的空目录对象。多个任务共用目录时允许安全复用，创建失败沿用已批准位置的失败策略。

目标内容对比仍递归覆盖所有已启用根目录，包括旧 DCIM、不同日期及改名副本。分类不降低 SHA-256 去重要求，也不使备用副本自动补传主位置。新版本不自动移动或重排已有内容。

目录整理不改变原件删除授权：本地、映射盘、直接 WebDAV 和 S3 保留原件；普通 SMB 凭据依旧执行锁定目标、源和完整内容二次核验。

## 验证

默认测试仅用临时合成卡、内存流及回环协议，不操作真实媒体。覆盖时间边界、损坏元数据、大视频跳读、时区跨日、规则和类型、只读规划、历史目录去重、创建目录、同名冲突、主备路径一致、路径越级及原件清理限制。原生窗口使用合成数据渲染。
