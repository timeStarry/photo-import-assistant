# 架构与数据安全

## 用户会话

`MainWindow` 的 WinForms 宿主处理托盘与设备通知，`FluentView` 和对话框使用 WPF/XAML。程序在登录用户的交互会话中运行；注销后不运行。登录自启开关只调整任务的登录触发器，保留手动启动能力。

状态保存在 `%LOCALAPPDATA%\PhotoImport\state.json`。文件通过临时写入与替换保存，并保留上一份 `.bak`。日志为 `agent.log`；`jobs` 和 `imports` 保存每文件操作与校验凭据。这些运行数据不提交到 Git。

## 卡片识别

Windows 设备事件触发扫描，并每四秒核对可移动磁盘。扫描在独立进程中执行，超时后重试。

登记令牌写入卡根目录 `.photoimport-id.json`。这是应用生成的 UUID，不是硬件序列号。传输前同时检查卡内 UUID、文件系统序列号、容量与源文件快照；盘符或 Windows Volume GUID 不作为独立身份凭据。

格式化会移除令牌，需要重新关联。完整克隆卡也会复制令牌；同时发现相同 UUID 时阻止导入。当前仅扫描 Windows 上报为可移动磁盘的设备。

## 位置与传输

位置支持绝对文件夹、UNC 路径和 HTTP(S) WebDAV URL。URL 转换为 Windows WebClient 路径，使用系统已有的网络凭据。应用不在配置中保存密码，也不接受嵌入凭据的 URL。

每批开始时冻结已启用位置的顺序和失败策略。每文件由限时子进程复制，界面保持响应。取消或拔卡会中止当前操作；无法确认子进程退出时禁止新操作。

本地文件先写临时文件、刷新并读回校验，再无覆盖地改名。同名文件即使大小相同也核对完整 SHA-256，不同内容使用带哈希的文件名。不导入文件系统链接或重解析点。

某些 WebDAV 驱动不支持改名，程序可使用 CREATE_NEW 无覆盖直写，再关闭写入句柄、重新打开最终文件并校验。这不是原子发布：中断时可能留下不完整的最终文件，但不会生成成功凭据或授权清理原件。Windows WebClient 仍可能限制大文件传输。

## 原件清理

只有显式 UNC 网络位置的成功校验凭据能进入清理流程。本地文件夹与映射盘副本始终保留原件，与位置优先级无关。

清理前重新锁定并验证源文件、目标文件及 SHA-256；不匹配则保留原件。删除按已验证文件句柄执行。对话框默认保留，X/Esc 取消且不保存“记住选择”。

保存到备用位置后不会自动补传到原首选位置。再次插卡或手动导入可以重新尝试。
